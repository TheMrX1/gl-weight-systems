# Универсальные gl-весовые системы хордовых диаграмм

Код, точные многочлены и вычислительные сертификаты исследования. Текст черновика: [LaTeX](report/main.tex), [PDF](report/main.pdf). Титульная страница и оглавление в черновике отсутствуют.

## Основные результаты

- Неизоморфные мутанты порядка 11 с различными универсальными gl-весами; выписаны оба полных многочлена и их разность.
- Для этой пары разность сохраняется после примитивной проекции; все соответствующие собственные поддиаграммы имеют одинаковые gl-многочлены.
- Построена мутационная четвёрка порядка 14 с четырьмя различными весами в настоящем представлении gl4 формы (2,1).
- Доказаны формула и классификация всех крюковых специализаций фиксированной пары порядка 11; все её прямоугольные специализации совпадают.
- Вычислен полный универсальный gl-многочлен K11 с независимым C1: 587 мономов.
- Получены прямоугольные и хроматические специализации авторского 9-вершинного графового сертификата.
- Для n=11,12,13,14 доказана непродолжимость коэффициента [c^floor((n-1)/2)] в примитивном sl2-весе до графового 4-инварианта. Здесь sl2 нормирован формой Киллинга.

Доказательства, определения операций мутации и точные границы утверждений приведены в тексте. Полный перебор мутантов и непродолжимость во всех n>=15 не заявляются.

## Сборка

Нужны CMake >=3.24, Clang или GCC с C++20 и 128-битными целыми, Python >=3.10 и заголовки Boost (в том числе Boost.JSON и Boost.Multiprecision). MSVC без поддержки `__int128` не подходит; на Windows можно использовать GCC/Clang из MSYS2.

```sh
git clone https://github.com/TheMrX1/gl-weight-systems.git
cd gl-weight-systems
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DBOOST_ROOT=/path/to/boost
cmake --build build --parallel 3
ctest --test-dir build --output-on-failure
python3 scripts/verify_results.py --matrix
```

Если Boost установлен в стандартном пути, `-DBOOST_ROOT=...` можно опустить. Во всех следующих командах рабочая папка — корень репозитория. Для Windows в командах ввода используйте PowerShell; расширение программы будет `.exe`.

## Ввод диаграммы

Слово — целые неотрицательные метки через пробел. Каждая метка должна встретиться ровно дважды. Например `0 1 0 1` — две пересекающиеся хорды. Универсальные gl-вычислители рассчитаны на порядок до 11; время зависит от структуры диаграммы.

Три значения универсального gl-веса:

```sh
build/evaluate_word --specialization gl "0 1 0 1"
```

Ответ содержит `values`, `primes`, `casimirs`: три числа относятся к трём различным конечным полям. Полный список Казимиров фиксированной длины включает и переменные, не встретившиеся в многочлене данного входа. Режим `--specialization sl` только обнуляет C1 и не является вычислением sl2-веса.

Обычный и примитивный gl-многочлены, их численные проверки:

```sh
build/gl_polynomial --primitive-polynomial "0 1 0 1"
```

Только обычный gl-многочлен в JSON:

```sh
printf '%s\n' "0 1 0 1" | build/symbolic_witness --word
```

Обычный и примитивный sl2-веса (другая нормировка и другая специализация):

```sh
build/sl2_primitive --word "0 1 0 1"
printf '%s\n' "0 1 0 1" | build/sl2_word_batch
```

Массив `primitive_scaled` кодирует H_D(t)=8^n*w_sl2(pi(D))(t/8), от младшей степени вверх. Если элемент массива равен h_k, коэффициент c^k равен h_k/8^(n-k). В `sl2_primitive` массивы `moment`, `primitive`, `leaf_primitive` относятся соответственно к обычному весу, проекции и проекции после добавления листа; последний имеет порядок n+1.

## Представления и поиск

```sh
build/representation_weights --N 4 --young "2 1" \
  --polynomial results/mutants11/D_ordinary.json \
  --polynomial results/mutants11/D_prime_ordinary.json
build/hook_difference 4 2 2
build/verify_4_7_witness
```

`representation_weights` считает центральный характер по длинам строк диаграммы Юнга, затем подставляет его в указанные многочлены. `hook_difference` сравнивает универсальную разность с общей формулой для крюка (N,a,b). Он относится к фиксированной паре, а не произвольному входному слову. `verify_4_7_witness` воспроизводит исходный пример через операторы долей и универсальную рекурсию. `tensor_pair_search` содержит поиск по предварительно вычисленным блокам долей; точные определения и ограничения метода описаны в черновике.

Для четырёх мутаций порядка 14 можно повторить независимую свёртку по модулю 65521:

```sh
build/mutation_tensor "0 1 2 3 4 1 5 0 4 6" \
  "13 11 12 9 7 8 11 7 10 8" "3 5 6 2" "10 13 12 9" 65521
```

Скалярные веса по всем пяти полям, оценка абсолютной величины и точная целочисленная реконструкция сохранены в `results/mutants14/certificate.json`. Эта программа не вычисляет полные универсальные многочлены четырёх диаграмм порядка 14.

## Проверки примитивных сертификатов

```sh
python3 scripts/verify_results.py --matrix
build/graph_corank certificates/order13/certificate_input.json
build/graph_diagonal certificates/order13/certificate_input.json
build/graph_pairs certificates/order13/certificate_input.json
build/sl2_direct_matrix certificates/order13/certificate_input.json 3
```

Общая проверка заново считает 82 полных примитивных sl2-полинома: 18 порядка 11, 18 порядка 12, 23 порядка 13 и 23 после добавления листа. С `--matrix` выполняются ещё 184 независимые прямые матричные проверки (23 диаграммы, восемь представлений). Ранги и рациональные суммы считаются точно, без модульной реконструкции.

Три программы `graph_*` непосредственно пересчитывают графовые полиномы: корранговый, с диагональными возмущениями и раскрасками парами цветов. Они принимают JSON-массив графов с полями `id`, `n`, `edges`; для контрольной sl2-калибровки `graph_pairs` также читает `primitive_scaled`. В корранговых формулах используется переменная N, не ранг выбранного представления из предыдущих команд. Полный пересчёт раскрасочного полинома для 23 графов занимает несколько минут.

## Полный K11

```sh
python3 scripts/reconstruct_K11.py
```

По сохранённым F1,...,F11 команда точно восстанавливает полный gl-многочлен из разложения на бесследовую часть и центр; проверяет сокращение отрицательных степеней N. Уже существующие отличающиеся результаты не перезаписываются. Для расчёта F_k заново нужен отдельный сжатый вычислитель:

```sh
cmake --build build --target symbolic_traceless_compressed --parallel 2
```

Свежий K11 требует значительных ресурсов; исходные результаты сохранены, чтобы их проверка не требовала повторения тяжёлого этапа. Чтение `results/K11/K11.txt` не запускает вычислений.

## Файлы результатов

| Папка | Назначение |
|---|---|
| `results/mutants11` | Четыре диаграммы; 521-мономные обычные и 138-мономные примитивные полиномы; 27-мономная разность |
| `results/mutants14` | Четыре различных специализированных веса и полный сертификат реконструкции |
| `results/K11` | K1–K11 и F1–F11, полный K11 в TXT |
| `results/hooks` | Разность, разложение по двум геометрическим последовательностям, образы Хариш–Чандры |
| `results/graphs9` | Прямоугольные и хроматические значения 9-вершинного сертификата |
| `certificates/order9` | Авторский сертификат в развёрнутом формате с хордовой реализацией |
| `certificates/order11` | 18 диаграмм, рациональные коэффициенты, полные графовые полиномы |
| `certificates/order12` | Перенос сертификата порядка 11 добавлением листа |
| `certificates/order13` | 23 диаграммы, три полных графовых полинома и независимые матричные проверки |

В универсальных gl-полиномах JSON каждый моном задаётся `coefficient` и `powers`: `powers[0]` — степень N, `powers[k]` — степень Ck. Коэффициенты записаны строками для сохранения точности. В файлах примитивных графовых сертификатов Q/P заданы в мономиальном базисе, S — в биномиальном базисе binom(N,k). Обозначение Q в JSON соответствует U в тексте.

## Текст и рисунки

```sh
python3 -m pip install -r requirements.txt
python3 scripts/draw_figures.py
tectonic -X compile report/main.tex
```

Tectonic: https://tectonic-typesetting.github.io/ . Используются Times New Roman (основной), Arial и Menlo; для систем без этих шрифтов в исходнике предусмотрены Liberation Serif/Sans и DejaVu Sans Mono. Готовые рисунки находятся в репозитории и не требуют Matplotlib для простой сборки текста.

`verification.json` содержит отчёт проверки опубликованной версии. `provenance.json` связывает перенесённые исходники с исходными файлами исследования; рабочие папки исследования при подготовке публикации не изменялись. Сообщения коммитов на русском описывают назначение файлов.
